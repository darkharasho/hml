# HML Nexus Mods Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Browse, install and update Nexus Mods files in any game's profiles, with a pasted personal API key, `nxm://` downloads for free accounts, and Nexus-only games that deploy mods into the game folder.

**Architecture:** A main-process Nexus client reads search, game and file data from the keyless v2 GraphQL API and gets download links from v1 REST with the user's key. Downloads go through a new archive reader (zip, plus 7z through a bundled `7za`) into the existing `installZip`. Thunderstore games are matched to a Nexus domain by name (cached, overridable). Nexus-only games join the catalog with a `deploy` loader: the profile mirrors the game folder, and a deploy step copies enabled mods into the game folder with a manifest so they can be removed cleanly.

**Tech Stack:** Electron main (`fetch`, `safeStorage`, protocol handler, single-instance lock), `fflate`, `7zip-bin`, existing installer/profiles/services, React + zustand + Tailwind renderer.

**Spec:** `docs/superpowers/specs/2026-10-15-hml-design.md` (sections "Games: agnostic, searchable catalog", "Nexus Mods (plan 4)", "Mod identity").

## Global Constraints

- Vitest always runs with `--maxWorkers=2`.
- The renderer never imports Node modules. Every privileged action goes through `HmlApi` (`src/shared/ipc.ts`); new methods go in `METHOD_TABLE`.
- Every JSON write uses `writeJsonAtomic`. The data root is injected (`AppPaths`). Tests use a temp dir and an injected `fetch`. No test touches the network.
- Nexus mods are recorded with `source: { kind: 'nexus', domain, modId, fileId }`.
- The Nexus API key is stored only with `safeStorage` (the existing `SecretPort`). It is sent only as the `apikey` header to `https://api.nexusmods.com/v1/`, and it never crosses IPC to the renderer.
- Every Nexus request sends `Application-Name: HML`, `Application-Version: <app version>` and `User-Agent: HML/<app version> (<os.type()> <os.release()>; <process.arch>)`. Never impersonate another client.
- Never store or log the `email` field from `validate.json`.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Platforms: Windows + Linux.

### Facts verified against the live API (2026-10-16)

- **GraphQL endpoint.** `POST https://api.nexusmods.com/v2/graphql` (JSON `{query, variables}`) needs no key for `games`, `game(domainName)`, `mods`, `modFiles`.
- **`games` query.** `games(filter:{name:[{value, op:WILDCARD}]}, count, offset, sort:[{downloads:{direction:DESC}}])` matches a plain word as a substring (`skyrim` → 4 games). `*` characters match nothing. Node fields: `id name domainName modCount`.
- **`mods` query.** `mods(filter:{gameDomainName:[{value}], name:[{value, op:WILDCARD}], adultContent:[{value:false}]}, sort:[{<field>:{direction:DESC}}], offset, count)` returns `{totalCount, nodes}`. Pagination is offset and count.
  - Sort fields: `relevance, name, downloads, endorsements, updatedAt`.
  - Node fields: `modId name summary author version pictureUrl thumbnailUrl downloads endorsements updatedAt adultContent`.
- **`modFiles` query.** `modFiles(modId: ID!, gameId: ID!)` takes the numeric game id (R.E.P.O. = 7398), not the domain.
  - Fields: `fileId name version category categoryId primary size sizeInBytes date`.
  - `category` is one of `MAIN UPDATE OPTIONAL OLD_VERSION MISCELLANEOUS REMOVED ARCHIVED`.
  - `date` is unix seconds. `size` is KB. `sizeInBytes` is a string and may be `"0"`.
  - `primary` is unreliable: the newest MAIN file can have `primary: 0`.
- **`validate.json`.** `GET https://api.nexusmods.com/v1/users/validate.json` with header `apikey` returns `{user_id, key, name, is_premium, is_supporter, email, profile_url}`. A bad key returns 401. It doesn't count against the hourly limit.
- **`download_link.json`.** `GET https://api.nexusmods.com/v1/games/<domain>/mods/<modId>/files/<fileId>/download_link.json[?key=<key>&expires=<expires>]` returns `[{name, short_name, URI}]`, preferred first.
  - Errors: 403 free account without key; 400 bad key or expires; 404 file not found; 410 link expired.
  - The `URI` host is a CDN (e.g. `cf-files.nexusmods.com`) and needs no headers.
- **Rate limits.** Exceeding them returns 429. The headers `X-RL-Hourly-Remaining`, `X-RL-Hourly-Reset` (ISO time) and `X-RL-Daily-*` are sent.
- **`nxm://` links.** They look like `nxm://<domain>/mods/<modId>/files/<fileId>?key=<key>&expires=<unix>&user_id=<id>` and come from the site's "Mod Manager Download" button.
- **Handler delivery.** The link arrives in `process.argv` on first launch and in the `second-instance` event's argv afterwards. Find the argument that starts with `nxm://`; it isn't always last.
- **Archive layouts.** Nexus archives for BepInEx games are mixed: a bare dll, `plugins/<Mod>/…` plus `manifest.json`, or `BepInEx/plugins/…`. The existing `planInstall` already routes all three.
- **Archive formats.** Many archives for other games are `.7z`. `7zip-bin`'s `7za` handles zip and 7z but not rar.
- **No Steam app ids.** The Nexus schema has no Steam app id field, so domains are matched by name.

## Decisions this plan makes (the spec leaves them open)

- **Authentication.**
  - The personal API key is the login, as the spec says. Settings labels it "Personal API key".
  - The validated user `{name, isPremium, userId}` is cached in main memory for the session, never the email.
  - Registering HML with Nexus for SSO is out of scope.
- **Domain for a Thunderstore game.**
  - Resolution order: `settings.nexusDomainOverrides[label]`, then a cached lookup, then a live lookup.
  - The live lookup is `games(filter:{name:[{value: displayName, op: EQUALS}]})`, then the first node whose `domainName` equals the label with non-alphanumerics removed (`lethal-company` → `lethalcompany`), else null.
  - The cache lives in `cache/nexus-games.json` as `{ [label]: { domain: string|null, gameId: number|null, checkedAt } }` and is re-checked after 7 days.
  - A null domain means "not on Nexus Mods". The user can set a domain by hand.
- **Nexus-only games.**
  - `searchGames(query)` with a query of 2+ characters also runs the Nexus `games` search (count 20). It appends games whose domain no catalog game resolves to (cached domains only, never a live lookup per game).
  - Each appended game has label `nexus-<domain>`, `loader: 'deploy'`, `supported: true`, `steamAppId: null`, `installRules: []`, `packageIndex: null`.
  - Picking one calls `addNexusGame(domain)`, which persists it in `nexus-added-games.json`. `getCatalog` merges added games into the catalog.
  - Nexus search failures leave catalog results untouched.
- **Deploy loader.**
  - A deploy game's profile dir mirrors the game folder.
  - Archives install as-is (normalized and checked for unsafe paths), with one wrapping top-level folder stripped when it is the only top-level entry. Every file is disableable.
  - The game folder comes only from `gamePathOverrides`.
  - **Deploy:** first removes any current deployment. It then copies each enabled mod's files (later-installed mods win conflicts) into the game folder, moving any pre-existing game file to `games/<label>/deploy-backup/<path>` first. The deployment manifest `games/<label>/deployment.json` is written before the first copy.
  - **Remove mods:** copies any file whose size or mtime changed since deploy back into its mod in the profile, deletes the deployed files, restores backups and removes only directories the deploy created.
  - **Launch:** HML doesn't launch deploy games. The launch bar shows **Deploy mods** / **Remove mods** and the user starts the game normally.
- **Archives.**
  - zip goes through `fflate`. 7z (magic `37 7A BC AF 27 1C`) is extracted by `7za` into a temp dir, read into memory, and the temp dir removed.
  - rar (magic `52 61 72 21`) is refused with `HML can't open .rar archives yet. Download it from Nexus Mods and install the extracted files from a zip.`
  - Extracted symlinks are skipped.
  - Downloads are capped at 1 GiB, held in memory, with a 10-minute deadline.
- **Mod identity.**
  - Package id is `nexus-<modId>`, so the profile's plugin folder is stable across file updates.
  - Name is the Nexus mod name. Version is the file's `version`, or the mod's `version` if the file's is empty.
  - A local mod whose id equals the archive's manifest name is replaced, the same rule as plan 2.
- **Which file.**
  - The detail view lists MAIN, UPDATE, OPTIONAL and MISCELLANEOUS files, newest first, each with Install.
  - "Install" on a search result installs the newest MAIN file by `date`.
- **Updates.**
  - Only mods installed from a MAIN file are checked. An update exists when the newest MAIN file's `fileId` differs from the installed one and its `date` is later.
  - Checks run alongside the Thunderstore and GitHub checks; there's no background auto-install.
  - Premium accounts update in place. Free accounts get the file page opened in the browser, and the `nxm://` link completes the update.
- **Downloads by account type.**
  - Premium installs call `download_link.json` without key and expires.
  - Free installs return `{ kind: 'open-website', url }`, where url is `https://www.nexusmods.com/<domain>/mods/<modId>?tab=files&file_id=<fileId>`. The renderer opens it.
- **`nxm://` handler.**
  - HML never claims `nxm://` silently, because Vortex may own it. Settings has **Use HML for Nexus downloads**, which registers.
  - Windows: `app.setAsDefaultProtocolClient('nxm')`.
  - Linux, packaged only: write `~/.local/share/applications/hml-nxm.desktop` (`Exec="<execPath>" %u`, `MimeType=x-scheme-handler/nxm;`, `NoDisplay=true`), then run `xdg-mime default hml-nxm.desktop x-scheme-handler/nxm`.
  - In dev, registering is refused with `Nexus download links can only be handled by an installed build of HML.`
- **`nxm://` routing.**
  - The link's domain picks the game: an added Nexus game, or a catalog game whose cached or overridden domain matches. It installs into `settings.lastProfile[label]`.
  - It refuses a link whose `user_id` isn't the logged-in user.
  - If no game matches, it emits a failure telling the user to open that game in HML first.
- **Adult content.** Hidden by default. The Nexus browse has a **Show adult content** toggle.

## Review Focus

1. **Free account clicks Install, or a link expires or was made for another account.** The browser opens the right file page. An expired or foreign `nxm://` link shows a readable error and installs nothing. (Task 5 tests for 403 → `open-website`, 410 message, user-id mismatch in Task 6)
2. **An archive is .7z, .rar, corrupt, or contains `../` paths or symlinks.** 7z installs, rar gives the exact message, corrupt archives give a readable error, and nothing outside the profile is written. (Task 2 tests)
3. **Remove mods after the game changed a deployed config file, after an overwritten original game file, or after the profile was deleted.** Changed files are kept in the profile, originals come back, and nothing HML didn't deploy is deleted. (Task 4 tests)
4. **Nexus unreachable, rate limited, or the key revoked.** Search shows a readable error without breaking Thunderstore browsing. A 429 message names when to retry. Game search still returns catalog games. (Task 1 error tests, Task 3 search-failure test)
5. **The API key leaks.** It never reaches the renderer, logs, error messages, the GraphQL endpoint or the CDN host. (Task 1 header tests, Task 5 status test)

Rules:
- **Search sort.** Sort maps `relevance→relevance, downloads→downloads, endorsements→endorsements, updated→updatedAt, name→name (ASC)`, everything else DESC. Empty text with `relevance` sorts by downloads.
- **Search filters.** `includeAdult: false` adds `adultContent:[{value:false}]`.
- **Key placement.** The key goes only in the `apikey` header and only on `https://api.nexusmods.com/v1/` URLs. GraphQL and the CDN `URI` get the plain headers.
- **Error messages.** Messages never contain the key.
  - 401 on validate: `Nexus Mods didn't accept that API key.`
  - 429: `Nexus Mods' rate limit was reached. Try again after <local time of X-RL-Hourly-Reset>.`, falling back to `Try again later.`
  - Network failure: `Couldn't reach Nexus Mods. Check your connection and try again.`
  - GraphQL `errors[]`: `Nexus Mods search failed: <first message>`
  - `download_link` 403: throws a `NxPremiumRequiredError` (exported class).
  - 410: `This Nexus download link has expired. Click "Mod Manager Download" again.`
  - 400: `This Nexus download link isn't valid for your account.`
  - 404: `That file is no longer on Nexus Mods.`
- **Timeouts.** API calls time out after 30 s and downloads after 600 s, via `AbortSignal.timeout`.
- **Download size.** Downloads over `NX_MAX_DOWNLOAD` (by `Content-Length` or bytes read) throw `This file is larger than 1 GB, which HML can't install yet.`

**Interfaces:**

  - Return relative posix paths as names.

Rules:
- **Setting the key (`nxSetKey`).**
  - Trim the key. Null or empty removes it and returns null.
  - Keys with whitespace or control characters, or longer than 512 characters, throw `That doesn't look like a Nexus Mods API key.`
  - Check `secrets.isAvailable()` before any request (storage message, with `what` = `'a Nexus Mods API key'`).
  - Validate, then save, then cache the user.
- **Status (`nxStatus`).** Validates the saved key once per session (re-validates after `nxSetKey`). A 401 there clears the cached user but not the key. `handler` comes from Task 6 (`'not-registered'` until then).
- **Game without a domain.** Every method for a game with no domain throws `<displayName> isn't on Nexus Mods. Set its Nexus domain in the game's menu.`

  - Without a key, throw `Add your Nexus Mods API key in Settings to download.`

- **Updating (`nxUpdate`).** Per mod: premium → installed; free → `open-website` for the newest MAIN file. A failure on one mod doesn't stop the rest; failures are thrown together after the loop, as GitHub does (`Updated N of M Nexus mods. <name>: <error>`).

### Task 6: `nxm://` links

**Files:**
- Create: `src/main/nexus/nxm.ts`
- Modify: `src/main/nexus/service.ts`, `src/main/services.ts`, `src/main/index.ts`, `src/shared/ipc.ts`
- Test: `tests/main/nexus/nxm.test.ts`, `tests/main/services.test.ts`

**Interfaces:**
- Produces from `nxm.ts`:
  - `NxmLink { domain: string; modId: number; fileId: number; key: string; expires: number; userId: number | null }`
  - `parseNxm(raw: string): NxmLink | null`. It requires the `nxm:` protocol, a domain matching `^[a-z0-9]+$`, the path `/mods/<digits>/files/<digits>`, and a non-empty `key` and numeric `expires`. Anything else returns null.
  - `findNxmArg(argv: string[]): string | null`
  - `HandlerPort { status(): Promise<'registered' | 'not-registered' | 'unavailable'>; register(): Promise<void> }`
  - `linuxDesktopEntry(execPath: string): string`
- `ServiceDeps` gains `nxmHandler: HandlerPort`.
- Produces on `HmlApi`: `nxRegisterHandler(): Promise<void>`. `nxStatus().handler` reads `nxmHandler.status()`.
- `handleNxm(raw)`:
  - Parses the link.
  - Checks the logged-in user (`This download link is for a different Nexus Mods account.` when `userId` mismatches).
  - Finds the game (`Open <domain> in HML before downloading its mods.` when none matches) and the profile (`Pick a profile for <displayName> in HML first.`).
  - Installs and emits `nexus-installed`. It never throws: failures emit `nexus-failed` with the message, and an unparseable link emits `That isn't a Nexus Mods download link.`
- `index.ts` implements `HandlerPort`. It uses `app.isDefaultProtocolClient('nxm')` on Windows. On Linux it compares `xdg-mime query default x-scheme-handler/nxm` with `hml-nxm.desktop`, and `unavailable` when `!app.isPackaged`.
- `register()` follows the Decisions section. The dev refusal message is `Nexus download links can only be handled by an installed build of HML.`
- `index.ts` takes `app.requestSingleInstanceLock()` and quits when it isn't granted. On `second-instance` it focuses the window and passes `findNxmArg(argv)` to `handleNxm`. The first-launch `process.argv` link is handled after the window's `did-finish-load`, so the renderer receives the event.
