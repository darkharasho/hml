# HML Share Codes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Export a profile as a `.hml` file or a short share code, and import someone else's file or code to rebuild the same mod list at matching versions, with configs, listing anything that can't be resolved.

**Architecture:**
- A small Cloudflare Worker (`worker/`) stores uploaded `.hml` zips in KV under 10-character Crockford base32 codes, rate limited per IP with the Workers rate-limiting binding.
- In HML's main process, `share/hmlFile.ts` builds and reads `.hml` zips, and `share/client.ts` talks to the Worker.
- `share/service.ts` exports, uploads, previews and imports. Imports reuse the existing Thunderstore, GitHub and Nexus install paths, so each mod goes through the same planner and records.
- The renderer gets a Share dialog and an Import dialog.

**Tech Stack:** Cloudflare Workers + KV + rate-limiting binding (deployed with wrangler 4), `fflate`, zod, the existing services and installer, React + zustand + Tailwind.

**Spec:** `docs/superpowers/specs/2026-10-15-hml-design.md` (sections "Share codes (plan 5)" and "Mod identity").

## Global Constraints

- Run vitest with `--maxWorkers=2`.
- The renderer never imports Node modules. New privileged actions are `HmlApi` methods in `METHOD_TABLE` (`src/shared/ipc.ts`).
- Every JSON write uses `writeJsonAtomic`. Tests use temp dirs and an injected `fetch`. No test touches the network.
- Spec values:
  - Worker routes: `POST /v1/profiles` with the `.hml` zip as the body (max 10 MB, rate limited per IP) returns `{ code }`. `GET /v1/profiles/:code` returns the zip.
  - Codes are 10 characters of Crockford base32.
  - The `.hml` file is a zip holding `export.json` plus the profile's `BepInEx/config/**`.
  - `export.json` is `{ formatVersion: 1, game, profileName, mods: [{ source, version, enabled }] }`, where `source` is the `ModSource` union.
  - Import resolves each mod to its exact version and lists unresolved entries instead of failing silently.
- Never send the user's email, GitHub token or Nexus key to the Worker. An upload carries only the `.hml` bytes.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Platforms: Windows + Linux.

## Decisions this plan makes (the spec leaves them open)

- **Worker storage:**
  - KV key `p:<CODE>`, value = the zip bytes.
  - `expirationTtl` is 365 days (31536000 s), so stored profiles expire a year after upload.
  - Rate limit: 5 uploads per 60 s per `CF-Connecting-IP`, binding `UPLOAD_LIMITER`, namespace id `"5001"`.
  - GETs aren't rate limited.
  - A collision on a new code retries up to 3 times, then returns 500.
- **Worker validation:**
  - The `content-length` header must be at most 10485760 (10 MiB), and the body is read with the same cap. Too big → 413 `{ error: 'too-large' }`.
  - The body must start with `PK\x03\x04`, otherwise 400 `{ error: 'not-a-zip' }`.
  - Rate limited → 429 `{ error: 'rate-limited' }`.
  - A code that isn't 10 Crockford characters after normalizing → 400 `{ error: 'bad-code' }`.
  - Missing → 404 `{ error: 'not-found' }`.
  - Unknown routes → 404. Other methods → 405.
  - A successful POST returns 201 `{ code }`.
  - A successful GET returns `content-type: application/zip` and `cache-control: public, max-age=86400, immutable`.
- **Code format:**
  - Alphabet `0123456789ABCDEFGHJKMNPQRSTVWXYZ`, 10 characters from `crypto.getRandomValues` (50 bits).
  - Shown to users as `XXXXX-XXXXX`.
  - Normalizing (shared by the Worker and HML) uppercases, drops spaces and `-`, and maps `O`→`0` and `I`/`L`→`1`. `U` is invalid.
- **`export.json` extras:**
  - Each mod entry also carries `name` (display only). On read `name` is optional, and unknown fields are ignored.
  - `game` is the game label, for example `repo` or `nexus-stardewvalley`.
- **Configs:**
  - The export includes regular files under `<profile>/BepInEx/config/`, recursively. Symlinks are skipped.
  - Over 10 MiB in total gives `This profile's config files are too large to share (over 10 MB).`
  - Deploy games have no profile-level `BepInEx/config`, so their `.hml` holds only `export.json`.
- **Import flow:**
  - `previewShare(input)` reads a code or a file, validates it and holds the bytes in main memory under a random token for 10 minutes.
  - `importShare(token, name)` creates a new profile and installs every resolvable mod in the `export.json` order. It then sets `enabled: false` where recorded, writes the configs over whatever the installs created, and returns an `ImportResult`.
  - Progress goes out as the existing `progress` event (`Importing <name>`, done, total).
- **Resolution, per source.** Unresolved reasons, verbatim:
  - **thunderstore:** call `tsInstall` with the exact version. An unknown package gives `Not on Thunderstore anymore.` An unknown version gives `Version <v> is no longer on Thunderstore.` Dependencies the export also lists are skipped as already satisfied.
  - **github:** call `ghInstall` with `https://github.com/<owner>/<repo>/releases/download/<tag>/<asset>`. A failure gives `Release <tag> isn't available on GitHub anymore.` A different sha256 adds a warning: `<owner>/<repo> <tag>: the release file changed since this profile was shared.`
  - **nexus:**
    - No API key → `Add your Nexus Mods API key in Settings to download.`
    - `open-website` → unresolved `Needs Nexus Mods Premium. Download it from the website.`, with `url`.
    - 404 or another error → the error message.
    - A domain different from the game's domain → `This mod is for a different game on Nexus Mods (<domain>).`
  - **local:** `Local file (<fileName>). Files aren't included in share codes.`
- **Game resolution on import:**
  - `export.game` must be a catalog label, or `nexus-<domain>`, which is added via `addNexusGame(domain)` when missing.
  - Otherwise: `This profile is for a game HML doesn't know (<game>).`
  - The preview names the game. The UI switches to that game after importing.
- **Upload consent:** the Share dialog uploads only when the user clicks **Create code**, and shows `Anyone with the code can download this profile's mod list and config files.`
- **Base URL:** `ServiceDeps.shareBaseUrl`. `index.ts` passes `process.env.HML_SHARE_URL ?? 'https://hml-share.project96.workers.dev'`.

## Review Focus

1. **A pasted code with typos or formatting.** Lowercase letters, `O`/`I`/`L`, spaces and dashes must normalize. A truly invalid code should show `That isn't a valid share code.` and never reach the network. (Task 2 tests)
2. **A malicious or broken `.hml`.** Zip-slip config paths, entries outside `BepInEx/config/`, a missing or invalid `export.json`, a huge archive, or a 7z or rar renamed to `.hml`. Each gives a readable error and writes nothing. (Task 2 tests)
3. **Partial import.** One unresolvable mod, a network failure in the middle, or a Nexus free account: the import still creates the profile with everything else, and lists each unresolved entry with its reason. It must never throw away what it installed. (Task 4 tests)
4. **The share server is unreachable or answers with an error.** 413, 429, a 5xx or a timeout each map to a readable message (`Share codes are unavailable right now. Export a file instead.` for network errors and 5xx). (Task 2 tests)
5. **Profile names.** Importing into a game that already has a profile with the same name gets a unique id. An empty or whitespace name falls back to the export's `profileName`. (Task 4 tests)

### Task 2: `.hml` files and the share client

**Files:**
- Create: `src/main/share/hmlFile.ts`, `src/main/share/client.ts`, `src/shared/shareCode.ts`
- Modify: `src/shared/types.ts`

**Interfaces:**
- Consumes: Task 1's `normalizeCode` and `CROCKFORD`. `src/shared/shareCode.ts` re-exports them from `../../worker/src/code` and adds `formatCode(code: string): string` (`ABCDE-FGHJK`).
- Shared types (in `src/shared/types.ts`):
  - `HmlExportMod { source: ModSource; version: string; enabled: boolean; name?: string }`
  - `HmlExport { formatVersion: 1; game: string; profileName: string; mods: HmlExportMod[] }`
  - `SharePreview { token: string; game: string; gameName: string; profileName: string; mods: { name: string; version: string; kind: ModSource['kind'] }[]; configFiles: number }`
  - `UnresolvedMod { name: string; version: string; kind: ModSource['kind']; reason: string; url?: string }`
  - `ImportResult { game: string; profile: ProfileManifest; installed: number; unresolved: UnresolvedMod[]; warnings: string[] }`
- Produces from `hmlFile.ts`:
  - `buildHmlFile(profile: ProfileManifest, profileDir: string): Promise<Uint8Array>`. `export.json` is first in the zip, with mods in profile order and `name` filled in.
  - `readHmlFile(data: Uint8Array): Promise<{ export: HmlExport; configs: Map<string, Uint8Array> }>`. Config keys are posix paths starting `BepInEx/config/`.
  - `MAX_HML_BYTES = 10485760`
- Produces from `client.ts`:
  - `uploadShare(o: { fetch: typeof fetch; base: string }, data: Uint8Array): Promise<string>`, which resolves the normalized code.
  - `downloadShare(o: { fetch: typeof fetch; base: string }, input: string): Promise<Uint8Array>`.

Rules:
- **Reading:**
  - Zip only, using `readZipEntries` with the size cap. Anything else gives `This isn't an HML profile file.`
  - `export.json` is validated with zod. Missing, invalid or `formatVersion` ≠ 1 gives `This HML profile file is damaged or from a newer HML.`
  - Entries other than `export.json` and safe paths under `BepInEx/config/` are ignored. A path with `..`, a backslash, an absolute path or a drive letter is unsafe.
  - More than 10 MiB of configs in total gives the size message from Decisions.
- **Client:**
  - Uploads send `content-type: application/zip`, the bytes only, and no other headers beyond `user-agent: HML`.
  - Downloads run `normalizeCode` first; null gives `That isn't a valid share code.` with no request made.
  - Status mapping:
    - 404 → `No profile has that share code. It may have expired.`
    - 413 → `This profile is too large to share (over 10 MB).`
    - 429 → `Too many share codes created. Try again in a minute.`
    - 5xx or network error → `Share codes are unavailable right now. Export a file instead.`
  - Timeouts: 30 s on each request. A download is capped at `MAX_HML_BYTES` while streaming.
